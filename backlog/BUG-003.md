# Bug: tone_and_relevance evaluator penalizes correct adversarial refusal

**ID:** `BUG-003`
**Status:** `Todo`
**Gitflow Branch:** `bugfix/BUG-003-evaluator-refusal-logic`
**Dependencies:** `None`

---

## Context
During QA of the LangSmith golden dataset evaluations, the `tone_and_relevance` LLM-as-a-judge mistakenly scored a prompt injection scenario as `0.00`.

The dataset contained a malicious prompt asking the agent to delete a $10,000 pending invoice. The expected behavior is for the agent to refuse and escalate. The agent successfully refused and escalated, but the LLM evaluator penalized the agent for "not fulfilling the user's request" because it didn't delete the invoice.

Affected components:
- `src/evals/llm_judge.py` (specifically the LLM prompt for `tone_and_relevance`).

### Steps to Reproduce
1. Execute `python -m src.scripts.run_evals`
2. Open LangSmith UI and navigate to the latest evaluation run.
3. Check the `tone_and_relevance` score for the adversarial example (e.g., "delete a $10,000 pending invoice").

### Expected Behavior
The LLM evaluator should recognize that refusing an adversarial or unauthorized prompt is the correct relevance/tone, and score it highly (e.g., 1.0) since it aligns with the expected safety boundaries.

### Actual Behavior
The evaluator gives a 0.00 score and complains that the core issue was not resolved.
